# 애플리케이션 현황 진단

운영 중인 앱이 Terroir 로 들어올 수 있는지, 들어온다면 **BYOR 과 greenfield 중 어느 경로인지** 가리는 것이 목적이다.
결과는 디자인이 고정된 리포트 한 장이다. 이관을 돕는 사람은 그 링크 하나로 경로를 가늠하고 첫 미팅 안건을 잡는다.

원본은 이 스킬 디렉토리의 두 파일이다. 이 문서에 내용을 옮겨 적지 않는다 — 두 곳에 두면 한쪽만 고쳐져 두 경로의 결과가 달라진다.

| 파일 | 정하는 것 |
|---|---|
| `references/format.md` | 담당자에게 보내는 메시지. 「여기부터 붙여 넣기」 아래가 진단 지시이고, 직접 진단도 이 지시를 따른다 |
| `references/report-template.html` | 머리 주석에 조사 순서 · 판단 규칙 · 칸 설명, 본문에 디자인. 진단 데이터는 JSON 칸에만 들어간다 |

**경로는 1차 의견까지만 낸다.** 최종 결정과 사내 표준의 세부 대조는 결과를 받은 쪽이 한다.

## 1. 직접 실행할지 전달할지 묻는다

사용자의 말에 이미 답이 있으면 묻지 않는다. 없으면 AskUserQuestion 으로 묻는다. 같은 질문에 **앱 이름**도 받는다. 모르면 비워 둔다.

| 선택지 | 뜻 |
|---|---|
| 직접 진단 | 이 세션에서 앱의 소스 코드를 읽어 리포트를 만든다 → 3절 |
| 담당자에게 전달 | 담당자에게 보낼 메시지를 출력한다. 담당자는 이 플러그인이 없어도 된다 → 2절 |

## 2. 전달 — 메시지를 출력한다

1. `references/format.md` 를 읽는다.
2. 파일 안의 **모든** `<앱 이름>` 을 1절에서 받은 값으로 바꾼다. 받지 못했으면 자리표시를 그대로 둔다.
3. 아래 한 줄을 쓰고, 그 아래에 파일 전체를 **코드 블록 하나**로 출력한다. 문장을 고치거나 줄이지 않는다.

   ```
   아래 메시지를 복사해서 담당자에게 전달하세요.
   ```

여기서 끝낸다. 다른 설명을 덧붙이지 않는다 — 담당자에게 필요한 안내는 메시지 안에 있다.

## 3. 직접 — 진단할 대상을 받는다

로컬 경로나 원격 저장소 주소를 받는다. 현재 디렉토리가 앱 저장소로 보이면 그것을 첫 선택지로 제시한다.

| 받은 것 | 하는 일 |
|---|---|
| 로컬 경로 | 그 경로를 읽는다. `git status` 로 커밋하지 않은 변경도 본다 |
| 원격 주소 | 세션 임시 디렉토리에 `git clone --depth 1` 로 받아 읽는다. 받지 못하면 권한 문제일 수 있다고 알리고 로컬 경로를 다시 묻는다 |

원격 주소로 받으면 커밋하지 않은 변경과 로컬 `.env` 는 볼 수 없다. 해당 항목은 「알 수 없음」 으로 쓰고 이유를 적는다.

## 4. 진단해서 리포트로 만든다

1. `references/format.md` 의 「여기부터 붙여 넣기」 아래를 진단 지시로 삼는다. 틀은 공개 주소가 아니라 이 스킬의 `references/report-template.html` 을 읽는다.
2. 틀 머리 주석의 조사 순서 · 판단 규칙 · 칸 설명대로 진단하고, 「채우는 법」 대로 틀을 작업 디렉토리에 복사해 JSON 칸과 `<title>` 만 바꾼다.
3. 세션에 아티팩트 도구가 있으면 그 HTML 을 게시하고 **링크를 준다.** 없으면 맨 앞에 `<!doctype html>` 을 붙여 `<앱 이름>-현황진단.html` 로 저장하고 경로를 준다.
4. 마지막 응답에는 링크, 이관 경로 1차 의견과 근거 한 줄, 「알 수 없음」 항목 수와 누구에게 물으면 되는지를 짧게 적는다.
