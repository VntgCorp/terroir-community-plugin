# sprint-review

스프린트 리뷰 · 다음 스프린트 플래닝 보고서를 팀의 스프린트 방식에 맞춰 한 장짜리 페이지로 만듭니다.

## 무엇을 하는가

지난 스프린트에서 한 일, 계획과 실제가 얼마나 달랐는지, 다음 스프린트에 무엇이 들어가는지를 한 페이지에 모아 리뷰 · 회고 · 플래닝 회의에서 화면에 띄워 놓고 같이 봅니다.
맨 위 결론 블록만 읽어도 이번 스프린트가 어땠는지 알 수 있고 그 아래는 근거 자료입니다.

페이지는 여섯 부분으로 되어 있습니다.

| 부분 | 내용 |
|---|---|
| 결론 블록 | 한 문장 결론, 숫자 셋, 2주를 일의 종류별로 어디에 썼는지 막대 하나, 회고 세 칸(잘된 것 · 아쉬운 것 · 다음엔), 다음 스프린트 한 줄 |
| 지난 스프린트 | 끝낸 티켓 수, 묶음별 막대. 중간에 들어온 티켓은 점선으로 구분 |
| 끝낸 날 | 2주 달력에 날짜별로 끝낸 티켓 · 휴가 · 스프린트 경계 |
| 추정과 실제 | 처음 계획한 티켓 · 추정 없이 있던 일 · 중간에 들어온 일을 나눠 추정과 실제 비교, 어긋난 이유 |
| 대표 작업 전후 (선택) | 가장 큰 변화 하나의 전 · 후 · 확인한 방법 |
| 다음 스프린트 | 일할 수 있는 날(휴가 · 행사 · 긴 회의를 뺀 값), 추정대로 하면 어디까지 들어가는지, 완료 기준 |

처음 쓸 때 팀의 스프린트 방식을 묻습니다. 스프린트 길이, 경계 시각(예 목요일 15:00), 추정 단위, 작업 시간 기록 여부,
캘린더에서 뺄 일정의 기준입니다. 답은 `~/.claude/sprint-review/<팀이름>.md` 에 저장하고 다음부터는 묻지 않습니다.

작업 시간을 티켓에 기록하지 않는 팀이면 날짜별 활동(PR · 상태 변경 · 코멘트)으로 실제 시간을 근사하고
페이지에 근사치라고 적습니다.

설정에서 추정 기록을 켜면 스프린트마다 티켓별 추정 · 실제 · 차이 이유를 `~/.claude/sprint-review/<팀이름>-추정기록.md` 에 쌓습니다.
기록에서 「상시 업무는 스프린트마다 1.5일」 「후속 티켓은 추정의 절반」 같은 보정 기준을 뽑고, 다음 스프린트를 계산할 때 그 기준을 씁니다.

## 쓰는 법

설치합니다.

```
/plugin install sprint-review@terroir-community-plugin
```

실행합니다.

```
/sprint-review:sprint-review
```

또는 이렇게 말합니다.

- 「스프린트 리뷰 준비해줘」
- 「이번 스프린트 정리해줘」
- 「다음 스프린트 계획 짜줘」
- 「추정이랑 실제 비교해줘」

설정을 고치려면 「스프린트 리뷰 설정 다시 하자」라고 말합니다.

## 전제 조건

| | |
|---|---|
| 외부 도구 | 있으면 자동으로 씁니다. 없으면 그 부분만 직접 붙여 넣으면 됩니다.<br>· Jira 커넥터(Atlassian) — 티켓 · 추정 · 변경 이력 조회<br>· Google Calendar 커넥터 — 휴가 · 행사 · 긴 회의 조회<br>· `gh` CLI — 활동으로 실제 시간을 근사할 때 PR 조회<br>· claude.ai Artifact 도구 — 페이지 게시. 없으면 HTML 파일로 저장 |
| 접근 권한 | 조회할 Jira 프로젝트와 GitHub 조직의 읽기 권한. 팀 전체 범위로 쓰면 팀원 캘린더 일정 보기 권한(없으면 휴가 · 행사를 물어봄) |
| 다른 플러그인 | 없음 |

## 알려진 한계

- 작업 시간 기록이 없으면 실제 시간은 근사치입니다. 활동이 있던 티켓끼리 하루를 똑같이 나누므로 늦게까지 일한 날도 하루로 셉니다
- 회의 · 리뷰 같은 티켓 없는 일은 캘린더나 PR 에 흔적이 남은 것만 잡힙니다
- 캘린더 규칙은 단순합니다. 휴가 · 종일 행사는 하루, 2시간 넘게 이어진 회의는 반나절로 뺍니다. 팀 규칙이 다르면 설정에서 고칠 수 있습니다
- 추정 기록의 보정 기준은 쌓인 스프린트가 적을수록 흔들립니다. 근거 칸에 몇 스프린트에서 나온 값인지 함께 적고, 한 스프린트에서만 나온 기준은 참고로만 씁니다
- 이슈 트래커는 Jira 만 자동으로 조회합니다. 다른 트래커는 티켓 목록을 붙여 넣어야 합니다
- 다음 스프린트에서 어디서 끊을지는 제안만 합니다. 이슈 트래커의 값은 고치지 않습니다
- 페이지에 보안 취약점 상세 같은 민감한 내용이 들어가지 않게 씁니다. 그래도 공유 전에 내용을 한 번 확인해 주세요
