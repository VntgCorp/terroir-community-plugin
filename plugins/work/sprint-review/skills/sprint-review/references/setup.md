# 팀 설정 — 처음 쓸 때 묻는 것

팀 설정 파일이 없을 때 세 차례로 나눠 묻는다. 선택지가 있는 질문은 AskUserQuestion 으로 한 번에 최대 네 개씩 묻는다.
선택지 없이 답하는 것(팀 이름 · 프로젝트 키 · 회의 시각)은 대화로 묻는다.

연결된 도구로 알 수 있는 값은 묻지 않고 먼저 조회해 「이게 맞나요」로 확인한다. 예 Jira 가 연결돼 있으면
접근 가능한 사이트와 최근 스프린트 이름을 보여 주고 고르게 한다. 캘린더가 연결돼 있으면 반복 회의 중
리뷰 · 플래닝으로 보이는 일정을 찾아 경계 시각 후보로 보여 준다.

## 1차 — 누구의 무엇을 보나

| 질문 | 선택지 | 저장 키 |
|---|---|---|
| 팀 이름 | (대화로) | `team` |
| 보고서 범위 | 내 티켓만 · 팀 전체 | `scope` |
| 이슈 트래커 | Jira · 그 밖(목록을 붙여 넣음) | `tracker` |
| 스프린트 길이 | 1주 · 2주 · 3주 · 4주 | `length_weeks` |

Jira 를 고르면 사이트 · 프로젝트 키 · 보드를 확인한다. 팀 전체 범위면 팀원 목록(이름 · 이메일 · GitHub 계정)을 받는다.

## 2차 — 스프린트 경계와 추정

| 질문 | 선택지 | 저장 키 |
|---|---|---|
| 스프린트는 언제 나뉘나 | 리뷰 · 플래닝 회의가 시작하는 시각(예 목요일 15:00) · 이슈 트래커의 스프린트 시작 · 종료 시각 그대로 · 회의 날 하루 전체를 새 스프린트로 | `boundary` |
| 추정은 무엇으로 하나 | 시간 · 일 단위(이슈 트래커의 예상 시간 칸) · 스토리 포인트 · 추정하지 않음 | `estimate_unit` |
| 실제 시간은 어떻게 아나 | 작업 시간을 티켓에 기록함 · 기록하지 않음(활동으로 근사) · 비교하지 않음 | `actual_source` |
| 하루는 몇 시간으로 치나 | 8시간 · 7시간 · 6시간 | `hours_per_day` |

- 「회의가 시작하는 시각」이면 요일과 시각을 대화로 받는다. 이 경우 경계 날 오전은 이전 스프린트, 회의부터 새 스프린트다
- 스토리 포인트면 일수로 환산할지 묻는다. 환산하지 않으면 페이지의 추정 · 실제 · 용량을 모두 포인트로 쓰고 용량은 지난 세 스프린트의 평균 완료 포인트로 정한다
- 「활동으로 근사」면 GitHub 계정과 조직 이름을 받는다. GitHub 을 쓰지 않으면 이슈 트래커의 상태 변경 · 코멘트만으로 근사한다

## 3차 — 일할 수 있는 날과 공유

| 질문 | 선택지 | 저장 키 |
|---|---|---|
| 일할 수 있는 날을 어떻게 구하나 | 캘린더에서 자동으로 · 휴가 · 행사를 직접 알려 줌 · 평일 수 그대로 | `capacity_source` |
| 캘린더에서 무엇을 빼나 | 기본 규칙 그대로 · 직접 정함 | `capacity_rules` |
| 매 스프린트 있는 상시 티켓이 있나 | 있음(키를 대화로) · 없음 | `recurring` |
| 결과를 어떻게 공유하나 | claude.ai 아티팩트 · HTML 파일 | `output` |

**캘린더 기본 규칙**

- 휴가와 종일 행사는 하루를 뺀다
- 2시간 넘게 이어진 회의 블록은 반나절을 뺀다. 붙어 있는 회의는 하나로 친다
- 데일리 · 1시간 반 이하 회의 · 업무시간 밖 일정 · 거절한 일정은 빼지 않는다

마지막으로 지난 리뷰 페이지가 있으면 위치를 묻는다(선택). 있으면 그때 세운 목표와 계획 티켓을 비교에 쓴다.

## 저장 형식

`~/.claude/sprint-review/<팀이름>.md` 에 저장한다. 팀 이름의 공백은 하이픈으로 쓴다.

```markdown
# 스프린트 설정 — 예시 개발팀

- team: 예시 개발팀
- scope: 팀 전체
- members: 홍길동 <gildong@example.com> @gildong · 김철수 <cs@example.com> @chulsoo
- tracker: Jira — 사이트 example.atlassian.net · 프로젝트 PROJ · 보드 12
- length_weeks: 2
- boundary: 목요일 15:00 (경계 날 오전은 이전 스프린트)
- estimate_unit: 일 (이슈 트래커 예상 시간 칸)
- actual_source: 활동으로 근사 — GitHub 조직 example-org
- hours_per_day: 8
- capacity_source: 캘린더
- capacity_rules: 기본 규칙
- recurring: PROJ-090 (고객 문의 대응)
- output: claude.ai 아티팩트
- last_review: (지난 리뷰 페이지 링크)

## 메모
- Jira 스프린트 필드는 JQL 에서 `cf[10020]` 으로 조회해야 한다 (이름이 같은 필드가 둘)
```

「메모」에는 쓰다가 알게 된 것(조회할 때 걸린 점 · 팀이 정한 예외)을 더한다. 다음 실행이 같은 문제를 다시 겪지 않게 한다.

저장한 뒤 내용을 사용자에게 보여 주고 고칠 곳이 있는지 묻는다.
