# 이 마켓은 무엇인가

## 왜 만들었나

사내 Claude Code 스킬을 나누는 통로가 [`terroir-claude-plugin`](https://github.com/VntgCorp/terroir-claude-plugin) 하나뿐이었다.
그건 플랫폼개발팀이 검증해 제공하는 **모음집**이라, 구성원이 자기가 만든 스킬을 올릴 자리가 없었다.

그래서 개인 스킬이 흩어졌다 — 채팅에 zip 으로, 개인 레포로, 설치 스크립트로.
만든 사람도 쓰는 사람도 "그거 어디 있더라" 를 반복했다.

**이 마켓은 그 통로다.** 팀 채널의 품질 기준은 그대로 두고, 공유만 넓힌다.

## 두 채널의 역할

```
  terroir-claude-plugin          terroir-community-plugin
  ─────────────────────          ────────────────────────
  플랫폼개발팀이 만들고 검증      구성원 누구나 올린다
  떼루아 맵 단계별 표준 흐름      개인이 만든 무엇이든
  "이대로 하면 된다"              "이런 것도 있다"
  팀이 품질을 책임진다            올린 사람이 책임진다
```

**둘은 경쟁하지 않는다.** 팀 채널이 좁고 깊다면 여기는 넓고 얕다.
여기서 쓸모가 증명된 스킬이 나중에 팀 채널로 올라갈 수는 있지만, 그건 별도의 결정이고
여기 올리는 것과는 무관하다.

## 무엇을 보증하나

**형식만 보증한다.**

| 보증한다 | 보증하지 않는다 |
|---|---|
| 유효한 플러그인이라 설치가 된다 | 스킬이 의도대로 동작한다 |
| 이름이 겹치지 않는다 | 내용이 정확하다 |
| 소유자가 누구인지 적혀 있다 | 유지보수된다 |
| 필수 파일이 있다 | 안전하다 |

**품질 심사를 하지 않는 것은 의도된 설계다.** 심사하는 순간 올리는 문턱이 생기고,
그러면 이 마켓이 만들어진 이유가 사라진다.

대신 **출처가 항상 보인다.** 모든 플러그인에 소유자가 적혀 있고, 설치 명령에
`@terroir-community-plugin` 가 붙어 "동료가 올린 것" 임이 드러난다.

> [!important]
> 사내 레포에 있다는 것이 검증을 뜻하지 않는다.
> 설치 전에 `/plugin` 상세의 **Will install** 을 보고, 모르는 스킬은 디렉토리를 열어
> `SKILL.md` 를 읽어 보라.

## 어떻게 운영되나

**올리는 사람이 자기 것을 관리한다.**

- 플러그인마다 소유자가 있다. 소유자 없는 플러그인은 들어올 수 없다
- 자기 플러그인의 변경은 **CI 만 통과하면 본인이 머지한다.** 누구의 승인도 기다리지 않는다
- 플랫폼개발팀은 **뼈대만** 관리한다 — 문서 · CI · 분류 목록 · 기여 도구

내리기 · 소유자 이관 · 분류 변경처럼 올리기 말고 다른 일이 필요하면
[마켓을 바꾸는 절차](operations.md)에 전부 있다. 누가 무엇을 할 수 있는지는
[권한](permissions.md)이다.

**사람 대신 CI 가 본다.**

형식 검사는 전부 자동이다. 리뷰어가 없어서 PR 이 쌓이는 일이 없고, 규칙은 문서가 아니라
검사로 집행된다. CI 가 무엇을 보는지는 [스킬 제작 방법](authoring.md)에 있다.

**실행 코드에 제한을 두지 않는다.**

훅 · 스크립트 · 에이전트 · MCP 연동 — 플러그인이 담을 수 있는 것은 무엇이든 받는다.
그래서 **설치는 남이 쓴 코드를 실행하겠다는 결정이다.** 특히 훅은 세션이 시작될 때
자동으로 도는 것이라, 불러야 작동하는 스킬과 성격이 다르다.

CI 는 형식만 본다. 코드가 무엇을 하는지는 보지 않는다. 모르는 플러그인은
`/plugin` 상세의 **Will install** 로 무엇이 들어오는지 확인하고, 훅이 있으면
그 파일을 열어 보는 것을 권한다.

## 여기 올리지 않는 것

| | 어디로 |
|---|---|
| 떼루아 표준 흐름을 바꾸는 것 | `terroir-claude-plugin` — 플랫폼개발팀에 문의 |
| 사내 비밀·고객 데이터가 담긴 것 | 어디에도 올리지 않는다 |
| 특정 프로젝트 전용 스킬 | 그 프로젝트 레포의 `.claude/skills/` |

마지막 항목이 헷갈리기 쉽다. **여러 사람이 가져다 쓸 수 있어야 여기 올 자리가 있다.**
나 혼자 쓰거나 한 레포에서만 의미 있는 스킬은 그 레포에 두는 게 맞다.

## 버려진 스킬은 어떻게 되나

소유자가 떠나거나 더 이상 관리하지 않는 스킬이 쌓이는 것은 피할 수 없다.
지금은 **그냥 둔다** — 쓰는 사람이 있으면 쓰고, 없으면 묻힌다.

정리가 필요할 만큼 쌓이면 그때 기준을 만든다. 미리 만들지 않는다.
