# 버전업 경로

## 왜 올려야 하는가

**Claude Code 는 `version` 이 바뀌어야 설치본을 갱신한다.**

파일만 고치고 버전을 그대로 두면, 고친 내용이 **이미 설치한 사람에게 영원히 전달되지 않는다.**
본인 컴퓨터에서는 잘 되는데 남들은 옛날 것을 쓰는 상태가 된다.

그래서 **사용자에게 닿는 파일을 고쳤으면 같은 PR 에서 `version` 을 올린다.** CI 가 검사한다.

```
  사용자에게 닿는 파일            닿지 않는 파일
  ──────────────────────          ──────────────
  skills/                         README.md
  agents/ · commands/             CHANGELOG.md
  hooks/ · scripts/
  references/ · templates/
```

`README.md` 나 `CHANGELOG.md` 만 고친 PR 은 버전을 올리지 않아도 된다.

## 어디를 올리는가

`Major.Minor.Patch` 다. 기준은 **호환** 하나다.

> **호환 = 이전 버전에 기대던 것이 그대로 동작한다.**

기대는 쪽이 셋이다.

| 기대는 쪽 | 기대는 것 |
|---|---|
| 쓰는 사람 | 스킬 이름, 부르는 방식 |
| 쓰는 사람의 기존 산출물 | 템플릿 · 파일 형식 · 파일을 두는 위치 |
| 설치 환경 | 훅이 건드리는 설정 |

| | 언제 | 예 |
|---|---|---|
| **Major** `2.0.0` | 셋 중 하나가 **깨진다** | 스킬 이름을 바꾸거나 없앴다 · 기존 산출물을 새 버전이 읽을 수 없다 · 사용자가 설정을 고쳐야 한다 |
| **Minor** `1.1.0` | **새 능력.** 기존 것은 그대로 동작한다 | 스킬을 하나 더했다 · 기존 스킬에 할 수 있는 일을 더했다 |
| **Patch** `1.0.1` | 기존 동작·문구 수정 | 버그를 고쳤다 · 안내 문구를 다듬었다 · 절차 순서를 바로잡았다 |

**판단이 갈리면 Major 쪽으로 본다.** 올려서 손해 보는 것은 없고, 올리지 않아 남의 작업이
조용히 깨지는 게 비싸다.

### 자주 갈리는 경우

| | |
|---|---|
| 스킬 이름을 바꿨다 | **Major.** 쓰던 사람의 `/명령`이 사라진다 |
| `description` · `when_to_use` 만 바꿨다 | **Patch.** 단, 트리거 조건이 달라져 뜨지 않던 곳에서 뜨면 Minor |
| 템플릿 형식을 바꿨다 | 이전 템플릿으로 만든 산출물을 새 버전이 읽으면 **Minor**, 읽지 못하면 **Major** |
| 훅을 추가했다 | **Major.** 설치 환경이 바뀐다 |
| 참조 문서만 고쳤다 | 스킬이 읽는 문서면 **Patch** |

## CHANGELOG

**두 번째 버전부터** 쓴다. 초판(`1.0.0`)은 비교할 이전 버전이 없어서 적을 게 없다.

`plugins/<분류>/<이름>/CHANGELOG.md` 에 최신이 위로 쌓는다. 제목은 `## <version> - <YYYY-MM-DD>` 다.

항목을 **어떻게 쓰는지**는 [변경 이력 쓰는 법](https://github.com/VntgCorp/terroir-claude-plugin-public/blob/main/plugins/terroir-context/docs/changelog-writing.md)이 원본이다. 여기에 옮겨 적지 않는다 —
두 곳에 두면 한쪽만 고쳐져 어긋난다. Claude 에서는 `/terroir-context:changelog-write` 가 그 문서를
읽고 쓴다. `terroir-context` 는 온보딩이 설치해 둔다.

### 이 마켓이 고른 것

원본은 저장소마다 갈리는 여섯을 **그 저장소가 적는다**고 넘긴다. 이 마켓의 답이다.

| 항목 | 이 마켓 | 왜 |
|---|---|---|
| 스코프 접두 | **안 한다** | 플러그인마다 CHANGELOG 가 따로 있어 한 파일에 여러 플러그인이 섞이지 않는다 |
| 층을 둘로 나누기 | **안 한다** | 한 버전의 항목이 몇 개뿐이다 |
| 기여자 크레딧 | **안 한다** | 플러그인마다 소유자가 정해져 있고 CODEOWNERS 와 README 「소유자」에 이미 있다 |
| 파괴적 변경 별도 절 | **그런 변경이 있는 버전에만 한다** | 제목은 `### 파괴적 변경`, 종류 제목 중 가장 위. 무엇이 깨지고 무엇을 고쳐야 하는지를 함께 적는다. Major 라도 깨지는 것이 없으면 두지 않는다 |
| `Unreleased` 누적 | **안 한다** | 버전이 PR 마다 오른다. 쌓아 둘 구간이 없다 |
| 표 형식 | **안 한다** | 불릿으로 충분하다 |

## 사용자에게 어떻게 닿는가

```
  version 을 올린 PR 머지
        │
        ▼
  자동 업데이트가 켜진 사람       다음 세션 시작 때 받는다
  켜지 않은 사람                    claude plugin update 를 직접 돌려야 받는다
        │
        ▼
  /reload-plugins 또는 세션 재시작
```

자동 업데이트를 **켠 사람**에게는 다음 세션에 간다. **켜지 않은 사람**에게는 가지 않는다 —
그 사람이 직접 받아야 한다. 켜는 법과 그때 생기는 일은
[README 의 「업데이트」](../README.md#업데이트)에 있다.

## 마켓플레이스 자체의 버전

`.claude-plugin/marketplace.json` 의 최상위 `version` 은 **`.github/marketplace-header.json`
에서 온다. 손대지 않는다.**

이 값은 설치본 갱신을 일으키지 않는다. **사용자가 저장해 둔 마켓플레이스 등록이
아직 유효한지**를 표시하는 자리다 — 레포가 옮겨지거나 마켓 이름이 바뀌어 **재등록이 필요할 때**만
플랫폼개발팀이 올린다.

플러그인 하나가 바뀌는 것은 전부 플러그인 `version` 의 일이다.
